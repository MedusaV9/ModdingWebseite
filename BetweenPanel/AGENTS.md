# Between — Game Server Management Panel

**Between** is a self-hosted, cross-platform (Linux + Windows) game server management panel — think Pterodactyl / AMP / PufferPanel — living in `Between/`. Node.js/TypeScript backend (Express + ws), React 19 + Vite + Tailwind CSS v4 frontend, JSON document store (no external DB), direct process management (no Docker), SteamCMD + direct-download + custom installers.

The working log and the user feedback loop live in `UserFeedback.md` at the repo root: log what you do there, read the "Dein Feedback" section for new user instructions, and keep iterating until the user writes STOPP.

## Cursor Cloud specific instructions

- **Node**: use the nvm-provided Node 22.x. If `node`/`npm` are missing from `PATH` in a fresh shell, run `source ~/.nvm/nvm.sh` first. Package manager is **npm** (npm workspaces; lockfile is `Between/package-lock.json`).
- **Install**: `cd Between && npm install` (installs both workspaces `server/` and `web/`).
- **Run (dev)**: `cd Between && npm run dev` — starts the API server on `http://localhost:8484` (tsx watch) and the Vite web dev server on `http://localhost:5173` (proxies `/api` and WebSocket `/api/ws` to 8484). Open 5173 in dev.
- **Run (prod-like)**: `cd Between && npm run build && npm start` — backend serves the built frontend on 8484.
- **Tests**: `cd Between && npm test` (node:test via tsx; unit + full-stack API integration tests, no services needed). Blueprint catalog validation: `npm run validate` inside `Between/server`.
- **Lint / typecheck**: `cd Between && npm run lint` (oxlint, NOT eslint) and `npm run typecheck` (tsc noEmit in both workspaces).
- **First run**: the panel starts with a setup wizard (create the first admin account) at `/setup`. For automated tests, env vars `BETWEEN_SEED_ADMIN_USER` / `BETWEEN_SEED_ADMIN_PASS` seed an admin at boot. All runtime state (servers, users, backups, steamcmd) lives in `Between/data/` (gitignored) — delete it for a factory reset.
- **Gotcha**: game server child processes are spawned by the backend; restarting the backend dev process stops running game servers (they are attached children by design, and are auto-started again if `autoStart` is set).
- **Demo blueprint**: the `demo-echo` blueprint installs a tiny fake game server (pure Node) that supports console commands (`help`, `say`, `players`, `crash`, `stop`) — use it for fast end-to-end testing without downloading a real game.
- **RCON/A2S testing**: `Between/server/scripts/fake-srcds.mjs` simulates a Source dedicated server (Source RCON over TCP + A2S_INFO/A2S_PLAYER over UDP with challenge handshake). Create a custom blueprint with a `rcon` block pointing at it to test the RCON console path, player lists and `stop.type: 'rcon'` without a 30 GB game install (see `--help`-style args at the top of the script).
- **Real-game smoke tests (verified working in this VM)**: `minecraft-paper` — system Java is 21 (`/usr/bin/java`), which runs MC ≤1.21.x; MC 26.1+ needs Java 25, available at `/opt/java/jdk-25.0.4+7-jre/bin/java` (set the blueprint's advanced `JAVA_BIN` variable to that path). `valheim` — installs via SteamCMD (~1.7 GB, ~1 min); SteamCMD needs the 32-bit libs `lib32gcc-s1 lib32stdc++6` (already installed here via apt). Valheim only answers A2S queries when `PUBLIC=1`.
- **Version resolvers**: PaperMC uses the Fill v3 API (`fill.papermc.io`) — the old v2 API returns HTTP 410. Live smoke test for all resolvers: `cd Between/server && npx tsx scripts/test-resolvers.ts`.
- **Docker runtime (optional feature)**: servers can run as a host process (default) or in a Docker container (`runtime: 'docker'`), and the Pterodactyl egg importer's `docker-script` install steps run in throwaway containers. This is 100% optional — with no daemon the panel degrades gracefully (the runtime picker shows "no Docker daemon reachable"; process runtime is unaffected). The Docker client is hand-rolled over the daemon socket (`server/src/lib/docker.ts`); default socket `/var/run/docker.sock`, override with `BETWEEN_DOCKER_SOCKET`. The Docker-dependent integration tests (`server/tests/integration/{docker,eggs}.test.ts`) auto-skip when no daemon is reachable, so `npm test` stays green without Docker.
- **Docker is NOT in the update script** (system dependency, not an npm dep). To exercise the Docker runtime/egg features in a Cloud VM, install + start it yourself: install Docker Engine per the Cloud Agent docker-in-docker recipe (fuse-overlayfs storage driver + `iptables-legacy`), then `sudo dockerd &` (or `nohup sudo dockerd >/tmp/dockerd.log 2>&1 &`) and `sudo chmod 666 /var/run/docker.sock`. Verify with `docker version`.
- **Docker gotcha (this nested VM only)**: the sandbox's cgroup v2 is in "threaded" mode, so the daemon **cannot enforce container CPU/memory limits** — starting a container with a memory/CPU limit fails ("cannot enter cgroupv2 … threaded mode"). Leave the docker Memory/CPU limits EMPTY when testing here (the JVM `-Xmx` `MEMORY_MB` blueprint variable is unrelated and fine). Also container `memory_stats.usage` is often absent here, so per-container RAM shows 0 B while CPU/uptime/players are live — expected, not a bug.
- **Docker container survival**: game containers are labelled `between.server.id=<id>` and are *detached* (kept running) on panel shutdown, then re-adopted on the next boot. If you `pkill` the panel mid-test, orphaned game containers keep running until the panel re-adopts them (or you `docker rm -f` them by that label). Install containers are labelled `between.install=1` and are swept at boot.
- **Config formats**: config-file sync + the live config editor support `properties`, `ini`, `json`, `keyvalue`, `raw`, and (hand-rolled, comment-preserving, surgical) `yaml` + `toml` (`server/src/lib/yaml.ts` / `toml.ts`). These are deliberately a *subset* — see each file's header comment for documented limitations before extending. The config read/write API is `GET`/`PUT /api/servers/:id/configfiles` (`server.files.read` / `server.config`); it only touches blueprint-declared paths, resolved through `safeJoin`.
- **Game Library catalog**: `server/src/catalog/catalog.json` (curated, 60 entries) + `GET /api/catalog` / `POST /api/catalog/:id/add`. `egg-url` entries and the Blueprints "import egg from URL" feature fetch community egg JSON over the network through the SSRF-hardened `server/src/lib/nettrust.ts` (`fetchPublicJson`) — so those paths need **outbound internet**; `builtin` catalog entries and offline egg file/paste import do not. `nettrust`'s `allowPrivateHosts` hook is test-only and never wired to request input.
- **Blueprint count is 73** builtins (`npm run validate` prints the count). A handful of the round-11 additions have SteamCMD app IDs / start args marked "verify before relying on" in their notes — trust but verify a specific game's exact launch args before treating it as production-ready.
- **Web terminal (interactive shell)**: `docker exec /bin/sh` into a running container, bridged over a *dedicated* WebSocket at `/api/servers/:id/shell` (separate from the multiplexed `/api/ws` hub; handled by `ShellHub` in `server/src/ws/shell.ts`, wired in `app.ts`'s `upgrade` handler). It is **docker-runtime only** and gated on `server.config` (a shell = arbitrary code, same trust as the start-command override), so the Shell tab is hidden for process-runtime servers. Auth is the session cookie; the socket-hijack plumbing it shares with container attach lives in `docker.ts` (`hijack()` + `execCreate`/`execStart`/`execResize`). If you extend it, keep the per-message permission re-check and the buffered-output cap — both are load-bearing (a revoked session must die; a slow client must not grow panel memory unbounded).
- **Long-lived connection invariants**: both `WsHub` and `ShellHub` must revalidate the *originating session* after the handshake (logout/session revoke must close an open stream), cap inbound/outbound buffering, terminate errored clients, and clear their tracking maps on shutdown. Do not replace these checks with a handshake-only user snapshot.
- **Runtime lifecycle invariants**: every timer/stream spawned by `ServerInstance` must be owned and cleared by `cleanupAfterExit()` + `dispose()`; one-shot query refreshes coalesce; async interval bodies must contain rejections and avoid overlap. Console disk logging deliberately closes after idle and drops under stream backpressure instead of buffering without limit. Child lifecycles use `close` (not `exit`) so stdout/stderr are drained before teardown, and stdin must have an error listener for exit-race EPIPE.
- **Shutdown invariants**: `ServerManager.shutdownAll()` joins Docker adoption and cancels staggered autostarts; `ScheduleService.stop()` aborts/joins active waits; notifier fetches are timeout/abort bounded. When adding background work, give it an explicit owner and shutdown path.
- **UI design contract**: `Between/web/DESIGN.md` is the binding contract for all frontend work (Liquid Glass materials `.glass/.glass-strong/.glass-subtle`, motion utilities incl. `.stagger`/`.pressable` + full `prefers-reduced-motion` support, rem-based text rule with fluid root font, 44px touch targets on coarse pointers, `.table-scroll` for wide tables, blur budget: never put `backdrop-filter` in repeated list rows). Mobile chrome lives in `Layout.tsx`: floating glass bottom dock below `lg`, drawer for full nav, modals become bottom sheets below `sm` (`Modal.tsx`). Themes drive glass via `--glass-*` vars set in `applyTheme` (`data-theme-dark` hook, per-theme overrides — `slate-light` has its own AA-compliant semantic status tokens). i18n key parity en/de is compiler-enforced; add keys at the end of both files.
- **Current quality baseline (round 29)**: `npm test` = 439 total (419 pass + 20 Docker-skipped when no daemon), `npm run lint` has zero warnings, typecheck/build clean, 73/73 blueprints valid, `npm audit` has zero vulnerabilities.
- **Steam login (round 29)**: secrets are stdin-only (never argv/persisted/logged — `scrubSecrets` in `server/src/steam/loginflow.ts` guards every output path; keep it). Real SteamCMD wraps prompts in ANSI SGR — always parse through `stripAnsi`. Tests use `server/scripts/fake-steamcmd.mjs` via `BETWEEN_STEAMCMD_BIN`. Sessions are per machine; remote-node installs requiring login fail fast by design (v1). File-manager mutations (rename/copy/move/zip/extract) are local-only v1 (gateway `assertLocal`); extraction reuses the zip-slip-protected + budget-capped `unzip`/`extractTar` — never bypass those. Schedule triggers are a union (`cron` | `event`); event runs are debounced 30s per schedule; command templates render via the injection-hardened `lib/template.ts` (`Object.hasOwn`, single-pass). CSV exports must neutralize spreadsheet formula injection (see `AuditLog.tsx`'s `neutralizeFormula`). `Field` auto-wires label/hint a11y — don't bypass it with bare labels.
- **Multi-node (round 26)**: same codebase boots as a headless agent via `BETWEEN_MODE=node` + `BETWEEN_NODE_TOKEN` (≥16 chars; constant-time compare; Bearer header only — never URLs). Panel side: `server/src/nodes/` (service registry+health poll+reconcile, `ServerGateway` dispatch in routes, `NodeStreamBridge` one multiplexed WS per node re-broadcasting into WsHub under identical channel names). Permissions are ALWAYS panel-side; the agent trusts the panel token. Remote create embeds the blueprint JSON. v1 remote-unsupported ops return 400 and the UI hides them (settings PATCH, clone, config editor, reinstall, steam-update, docker pull, schedules, mods, backup lock/download, file rename/copy/zip). Mirrors live in the separate `remote_servers` collection — never bootable as local processes. Node baseUrl validation is shape-only BY DESIGN (admin-only, LAN is the use case). Zero-node setups must stay byte-identical. Test pattern: boot panel + agent in-process (`tests/integration/nodes.test.ts`). User guide: `docs/NODES.md`. A live test agent may run in tmux `node-agent` (port 8485, data dir `data-node1`, gitignored). Fonts are self-hosted (`web/public/fonts/`, no external requests — keep it that way). Backup retention: "keep last N unlocked" enforced in `BackupService.create()` (locked backups exempt; `null` inherits panel default, `0` unlimited). Generic webhook notifier (`notify.ts`): shape-only URL validation by design (admin-only setting; private/LAN receivers are the point — do NOT route it through nettrust), 10s timeout + stop-abort, payload contract documented in the file. Metrics history: host ring (720 samples) in `MetricsService`, per-instance ring (360) on `ServerInstance.resources` via `server/src/lib/ringbuffer.ts`; history endpoints support `?limit=N`; Dashboard/ConsoleTab seed sparklines from history then append live WS samples (keep the ts-dedupe at the seam). Web routes are code-split (`React.lazy` in `App.tsx`: ServerDetail/Blueprints/Catalog/Create/admin/Account/Appearance lazy, Login/Dashboard/Servers eager — keep new heavy pages lazy and don't import lazy-page internals from eager code or the chunk gets pulled back). PWA assets live in `web/public/` (favicon.svg, icons/, manifest.webmanifest). The no-Docker smoke must still return `/api/docker/status` with `available:false`, reject Docker-runtime creation cleanly, and leave process-runtime CRUD/console fully operational. UI conventions added in rounds 15–16: console surfaces use fixed `--console-text-*` tokens (theme-invariant), audit actions render via shared `web/src/lib/audit.ts` (humanized label + tint, raw key in `title`) on all surfaces, dates format via `setDateLocale` following the UI language, `.microlabel` is the only content micro-label spec, CardHeader-embedded actions are `size="sm"`, destructive dialogs always carry a Cancel, loading uses content-shaped `Skeleton` compositions on dashboard/servers/server-detail (spinners only for buttons/inline waits), and the zero-server dashboard/servers pages show first-run CTAs (create + game library).
