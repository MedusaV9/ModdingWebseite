# ProjectEclipse — Cursor Cloud dev notes

**PROJECT: ECLIPSE** is a Minecraft **1.21.1 / NeoForge 21.1.238** server-event mod ("Eclipse-Core", mod id `eclipse`), an anonymous hardcore-survival psychothriller. This Gradle project lives in the `ProjectEclipse/` subdirectory of the repo (the repo root also contains an unrelated website — do not mix them). See `README.md` here for the full architecture, command list, 14-day plan, config files, and server-pack list.

## Cursor Cloud specific instructions

- **Java**: build/run with **Java 21** (installed system-wide). There is no system Gradle — always use the wrapper `./gradlew` from inside `ProjectEclipse/`.
- **Build / run** (standard, documented in `README.md`): `./gradlew build`, `./gradlew runServer` (auto `--nogui`; write `run/eula.txt` `eula=true` first), `./gradlew runClient`. The **first** `./gradlew build` downloads NeoForge + the MC toolchain and can take 10–30 minutes — allow very long timeouts and do not abort it. Subsequent builds are seconds.
- **Client runs on the VM desktop**: `runClient` opens a real Minecraft window that can be driven/inspected via the desktop (computerUse). OpenAL audio has no device here (harmless warning). This is how the title screen, purple sky, artifact menu, etc. are visually verified.
- **v2 REQUIRES A FRESH WORLD**: the overworld dimension type is now `min_y -176 / height 640` (floating-disc world) — v1 saves fail to load. Delete `run/world` once after upgrading; the disc/limbo dimensions regenerate deterministically.
- **Mods folder layout** (all gitignored): `run/mods/` holds the full server-safe v2 matrix (Create 6.0.10, Aeronautics-bundled 1.3.0, Sable 2.0.3, Voice Chat 2.6.16, Farmer's Delight 1.3.2, Supplementaries 3.8.3 + Moonlight 3.1.1, Sophisticated Backpacks 3.25.71 + Core 1.4.77, CreateAddition 1.6.0 — exact jars in README "Server pack") and is loaded by BOTH `runServer` and `runClient`. `run/mods-client/` holds Sodium 0.8.12 + Iris 1.8.14-beta.1 — CLIENT-ONLY: they crash the dedicated server in early bootstrap (`NoClassDefFoundError: org/lwjgl/Version`), so copy them into `run/mods/` only for client runs and remove before server runs. `run/mods-disabled/` parks the old Sodium 0.6.13/Iris 1.8.12 pack, which Veil 4.3.0 REJECTS (it enforces sodium `[0.8.12-alpha.2+mc1.21.1,)` and is incompatible with Embeddium) — do not resurrect it.
- **Sodium + Iris (client target)**: the tested client runtime is `sodium-neoforge-0.8.12+mc1.21.1` + `iris-neoforge-1.8.14-beta.1+mc1.21.1`. The custom purple-sun sky and all Veil post pipelines self-disable (return to Iris) when a shaderpack is active, detected via Veil's first-party `foundry.veil.api.compat.IrisCompat` wrapped by `client/sky/EclipseIrisState` (boot log line: `Iris detected (via Veil IrisCompat)`); without a shaderpack the full custom sky + Veil FX render. Veil 4.3.0 is a REQUIRED runtime dependency (jar-in-jar'd from `maven.blamejared.com`).
- **RCON for headless server smoke-tests**: `run/server.properties` ships `enable-rcon=true`, `rcon.port=25575`, `rcon.password=eclipsedev`. Piping into `runServer` stdin does NOT work under Gradle — use RCON (no `mcrcon` binary installed; a ~40-line Python socket client suffices) to drive `/eclipse status`, `day set`, `stage set`, boss summon/kill, etc., then kill the server by specific PID.
- **Voice chat / gated mods are soft/optional deps** (see README "Server pack"): all external mods are installed alongside Eclipse-Core, NOT jar-in-jar (their assets are All-Rights-Reserved, and jar-in-jar mods cannot be disabled at the loader level). Progression gating is server-authoritative by namespace (`ModGate`), so the build has ZERO compile-time dependency on them. The Aeronautics bundle also ships Create: Offroad (`offroad` namespace, gated under the `aeronautics` key). Aeronautics 1.3.0 pins Create `[6.0.9,)` — don't downgrade Create below 6.0.10.
- **Stopping lingering game instances**: `runServer`/`runClient` leave a `net.minecraft...devlaunch.Main` JVM running that holds the world lock / GL context and RAM (~1–3 GB each). Stop them by **specific PID** (`ps -eo pid,args | grep devlaunch.Main`, then `kill <pid>`) — never blanket-kill. Gradle daemons are reusable and can stay.
- **All UI text is de_de + en_us** in `assets/eclipse/lang/`. The mod is intended to be MANDATORY on clients (anonymity + anti-cheat rely on it). NEVER edit the two lang JSONs by hand during parallel work: workers ship `docs/plans_v3/langdrop/<PKG>.json` ({"en_us":{...},"de_de":{...}}) and the integrator merges them with `python3 tools/langmerge/merge_langdrops.py` (enforces en/de parity).
- **Dev pack bootstrap on a fresh VM**: `python3 tools/modpack/fetch_dev_mods.py` downloads the full external server pack into `run/mods/` and Sodium/Iris into `run/mods-client/` (all gitignored) from Modrinth. `run/server.properties` MUST include `allow-flight=true` — the cutscene/freeze system holds players airborne for ~45 s gathers and the sanctum edge-glide floats players, which the vanilla floating kick otherwise disconnects.
- **RCON one-liner**: `python3 tools/rcon/rcon.py "<command>" [more...]` drives the running dev server (uses the shipped `rcon.password=eclipsedev`). `/dev status` prints the ops health dashboard; `/dev docs export` regenerates `docs/DEV_COMMANDS.md` from the live registry.
- **Sequence testing**: `/eclipse start_event` runs the full intro (limbo keel-over → disc hop → flight → vortex → lightning → burst → reveal → sunrise); every phase is FX-replayable standalone via `/eclipsefx sequence intro <PHASE>`, and `/eclipse stage set overworld <n> animate` runs the expansion cinematic. A restart mid-sequence deliberately skips to the end state. Eval/audit reports live in `docs/plans_v3/eval/`.
- **Treblo/Sonauto music API** (`tools/music/treblo_generate.py`, key via `TREBLO_API_KEY` env — never commit it): the WAF rejects Python-urllib UAs (send a curl-ish `User-Agent`), the status endpoint returns a BARE JSON string, `style_scale` silently defaults to 4.5 (passing `prompt_strength>1` requires explicit `style_scale: 1.0`), `negative_tags` are vocabulary-validated (invalid → 422), submissions are strictly sequential (concurrent → 403), and one generation costs 100 credits. Post-process to OGG **Vorbis** (`ffmpeg -c:a libvorbis`) — Minecraft cannot play the API's opus-in-ogg output. `treblo_generate.py` runs `postprocess()` automatically after each download (two-pass loudnorm −16 LUFS, 48 kHz stereo Vorbis, strips non-audio streams, ≤ 2.5 MB budget); NEVER copy `<id>_raw.ogg` into `assets/eclipse/sounds/music/` — install the postprocessed `<id>.ogg` and then run `python3 tools/music/validate_oggs.py` (parses Ogg/Vorbis headers; fails on Theora/Opus containers, >48 kHz raw uploads, non-stereo or over-budget files) before committing music changes.
- **Config-default changes need fresh config files**: gameplay configs (`config/eclipse/*.json`) write defaults once and then persist — after changing Java default tables (milestones/ores/wand/contracts/skilltree), delete the affected file (or the whole `run/config/eclipse/`) so dev worlds regenerate them; per-save worldgen freezes additionally require a world reset or `/eclipse-worldgen refreeze`.
- **Textures**: the large "hero" assets (title background/logo/panorama, purple sun, eclipse disc, artifact menu panel) and the small pixel-art item/block icons under `src/main/resources/assets/eclipse/textures/` are final art; the small textures are generated assets, not placeholders.
- **No text-based tests**: verification is `./gradlew build` (compiles, strict) + `runServer` clean boot + `runClient` manual/visual checks. There is no unit-test suite (there ARE `gametest/` classes compiled in, but no wired test task — treat them as executable documentation).
- **v5 config self-migration**: `goals.json`/`realtime.json` carry a `configVersion` (older files are backed up as `*.bak-v<N>` and regenerated) and `anticheat.json` carries `allowlistVersion` (new default mod-ids are UNIONED in, operator additions preserved) — so v5 defaults reach existing saves WITHOUT deleting configs; the day cadence default is now `interval`/2h (was daily 18:00), switchable via `/dev phase`.
- **Mod distribution**: `python3 tools/modpack/build_mrpack.py` builds `dist/eclipse-event-<ver>.mrpack` (Modrinth pack, download-references only; Aeronautics/Sable stay manual per `MANUAL_INSTALL.md`); the committed answer to "is Forgified Fabric API needed?" is NO — Sodium/Iris embed their sub-modules, which the anticheat allowlist covers (`fabric_api_base` etc.).
- **Pre-event vs started saves**: `LimboGate`+`PreEventSafety` only hold/protect players in limbo while the start event hasn't run; on a save where it has (like the long-lived dev world in `run/`), joining players spawn on the overworld disc and `execute in eclipse:limbo run tp` gets bounced back by the containment watchdog — use a fresh world to demo limbo.
- **Veil post pipelines are the mod's only raymarching surface.** `eclipse:storm_volume` and `eclipse:rift_volume` are true volumetric passes (Beer–Lambert march over 3-D fBm, scene-depth clamped); everything else under `pinwheel/post/` is a 2-D screen grade. **The trap that cost a full debug cycle: a raymarcher clamps its march to `DiffuseDepthSampler`, so ANY opaque depth-writing geometry the mod draws inside the volume silently truncates it.** The storm's legacy occluder dome at `r − 5` cut every ray after ~5 blocks and the storm rendered as a smooth black balloon; it now shrinks to a 30 % core (`StormWallRenderer.OCC_VOLUMETRIC_CORE`) whenever `StormVolumeFx.isVolumeStorm(id)` is true, and the EXO shell quads are skipped entirely for those storms (drawing both techniques paints a bright smooth rim around the volume — an "eggshell"). Before adding geometry near a volumetric effect, check whether it writes depth.
- **Silhouette lumps must fit inside `BOUNDS_MARGIN`.** In `storm_volume.fsh` the density field modulates an effective radius; if `max(rEff)·1.05` exceeds `BOUNDS_MARGIN` the bounds sphere clips the lumps flat and prints back the perfectly round edge the lumps exist to break.
- **Veil's `VeilRenderTime` is NOT available in pinwheel post shaders** (4.3.0 only injects it into vanilla `ShaderInstance`s). Feed a `Time` uniform from Java like `storm_interior`/`rift_glitch` do. `PostPipeline.getUniform` returns a non-null no-op `ShaderUniformAccess`, so the house code deliberately has no null checks. **"Aperture" is not part of Veil** — it is the Iris team's separate next-gen shader platform; Veil has no module by that name.
- **Glitch zone events**: `/dev glitch add <effect> <radius> <seconds> [x y z]` drops a silent, unannounced area shader (canonical id list in `glitchzone/GlitchZoneEffects.IDS`: `outline`, `datamosh`, `scanlines`, `invert`, `void`, `dome`); `/dev glitch test <effect>` previews on the caller only. Zones persist in `eclipse_glitch_zones.dat` and sync epsilon-gated, so no chat/title/bossbar ever fires.
- **Verifying render work on this VM**: there is no GPU — `runClient` uses llvmpipe at seconds-per-frame, so drive it via computerUse with 20–40 s waits and keep the window small. Screenshots are fine; smooth video is not. For anything server-authoritative (commands, gating, worldgen, economy) prefer `runServer` + `python3 tools/rcon/rcon.py "<cmd>"` — it boots in seconds. **`run/server.properties` is regenerated with vanilla defaults if it is missing**, which silently disables RCON and `allow-flight`; re-set `enable-rcon=true`, `rcon.password=eclipsedev`, `allow-flight=true` after a wipe.
- **Never add `data/minecraft/tags/...` files under `src/main/resources`** if `src/generated/resources` already ships that tag — both roots are merged into `processResources` and Gradle fails the build with a duplicate-entry error. Extend the generated file instead.
- **Photon Editor integration**: Photon 2.1.5 + LDLib2 2.2.29 ship in BOTH `run/mods` and `run/mods-client` (their network channels are NOT optional, so a Photon-equipped client cannot join a photon-less server). CRITICAL: LDLib2 must be the Modrinth "-all" FAT jar (`ldlib2-…-all.jar`, bundles `META-INF/jarjar/taffy-1.1.4.jar`); the slim maven jar crashes server boot with `NoClassDefFoundError dev/vfyjxf/taffy`. Our 228 `.fx` assets live in `assets/eclipse/fx/` (authored via `tools/photon/fxlib.py` generators — never hand-edit the gzip-NBT binaries; regenerate + `python3 tools/photon/fxlib.py validate`). All Photon FX are LAYER/REPLACE rows in `PhotonFxRegistry` with Quasar/vanilla fallbacks; loops are WINDOWED-only (hysteresis controllers); `reducedFx` or missing Photon degrades gracefully. Test in-game via `/dev photon status|test <fxId>` (quote the id: `/dev photon test "eclipse:boss/x" <x y z>`, and run it `execute as <player>` — it needs a player). RELOAD GOTCHA: `FXHelper` keeps every loaded `.fx` in a static `CACHE` map that **F3+T does not invalidate** — after regenerating an asset you must run `/photon_client clear_client_fx_cache` in CLIENT chat (it is a client command, so RCON cannot reach it; confirm via the `clear client cache fx: N` chat line in `run/logs/latest.log`). Without it you are testing the previously-loaded effect and every tuning change looks like a no-op.
