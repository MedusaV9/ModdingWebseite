# F-012 — Classic / Xbox area block & texture audit

**Scope:** everything the Xbox tutorial worlds (`eclipse:xbox_tu*`) render — the
`eclipse:classic_*` block set, its bundled textures, and the per-era surface remaps in
`tools/xboxworlds/variants.py`. Nothing outside the Classic/Xbox area was touched.

**Goal:** no AI-generated art anywhere in the Classic area, and a block set that is
period-correct for the Xbox 360 Title Update each world represents.

**Result:** 14 bundled classic textures audited, **13 replaced**, 1 already clean.
Every bundled classic texture is now generated by `tools/classicblocks/gen_textures.py`
from the vanilla 1.21.1 client resources. **No `variants.py` change was needed** — the
remaps were already period-correct (evidence below). **No world regeneration required.**

---

## 1. What the Classic area actually bundles

`tools/classicblocks/gen_assets.py` resolves the whole 188-block classic set to
`minecraft:block/*` textures; the console-era look is a client-side colour grade
(`xboxevent/XboxEraProfile` → `client/xbox/XboxEraFx`), not baked art. Only the
**geometry sheets** stay bundled, because vanilla renders chests, ender chests, beds,
signs and skulls as block ENTITIES and ships no block-atlas tile for them.

Verified by scanning every `textures` entry of every model under
`src/generated/resources` + `src/main/resources`: exactly **14** `eclipse:` textures are
referenced from the classic set (13 block + 1 item), matching
`gen_assets.OWN_BLOCK_TEXTURES` / `OWN_ITEM_TEXTURES`. There is no other custom art in
the Xbox area — `xbox_era` is a shader, `era_dust_motes` is a Photon `.fx` blob, and the
bundled world payloads contain only `eclipse:classic_*` ids plus `minecraft:air`.

## 2. How "AI-artig" was decided

Two measurements per texture, compared against the vanilla source the provenance file
claimed it was derived from:

* **colour ratio** — distinct RGB values ÷ opaque pixels. Pixel art quantises hard;
  vanilla block/entity art sits at 0.01–0.06. Painted or upscaled art explodes.
* **soft-step share** — fraction of neighbouring opaque pixel pairs whose channel delta
  is 1–6/255, i.e. an almost-invisible gradient. Vanilla sits at 0–2%. Airbrushed or
  diffusion-generated art sits at 10–45%.

The old set's `provenance.json` credited an external MIT resource pack, but that pack is
not vendored and no generator existed, so none of it was reproducible or verifiable.
Pixel-level comparison also showed the "planks" and "obsidian" bases shared only
**9–10 of 256** pixels with vanilla `oak_planks` and **0 of 256** with vanilla
`obsidian` — they were repaints, not derivations.

## 4. Replacement — `tools/classicblocks/gen_textures.py`

Deterministic (re-run is byte-identical), reads the same vanilla jar as
`gen_assets.py`, and rewrites `provenance.json` from the same table so the two cannot
drift. It asserts its output set equals `gen_assets.OWN_*_TEXTURES`.

| kind | textures | method |
|---|---|---|
| skull sheets | `skull_{creeper,skeleton,steve,wither_skeleton,zombie}` | `(0,0,32,16)` head crop of the vanilla skin |
| sign board | `sign_oak` | `(0,0,64,16)` crop of `entity/signs/oak.png` |
| bed sheet | `red_bed_sheet` | verbatim copy of `entity/bed/red.png` |
| cube chests | `chest_*`, `ender_chest_*` | vanilla chest UV faces re-assembled into 16×16 tiles |
| bed icon | `item/classic/red_bed` | drawn 16×16, 8 colours sampled from vanilla bed + oak planks |

**Cube-chest assembly.** Vanilla lays a box of size `(w,h,d)` at sheet offset `(u,v)`
out as `top (u+d, v, w×d)`, `left (u, v+d, d×h)`, `front (u+d, v+d, w×h)`. The chest lid
is `(14,5,14)@(0,0)`, the body `(14,10,14)@(0,19)`, the latch `(2,4,1)@(0,0)`. Stacking
the lid face on the body face gives a 14×15 block, edge-extended (never rescaled) to
16×16 so every output pixel stays a verbatim vanilla pixel and the tile keeps hard
edges. The latch is pasted straddling the lid seam exactly as on the 3D model.

**Verification** (all pass):

* 7 textures are **byte-identical** to their vanilla source crop.
* 6 chest composites have a colour palette that is a strict **subset** of the vanilla
  chest sheet — every pixel is a vanilla pixel.
* the bed icon's 8 colours are a subset of vanilla `entity/bed/red.png` +
  `block/oak_planks.png`.
* `tools/classicblocks/validate.py` → `OK — all validation checks passed`
  (188 blocks, 156 baked palette ids covered, textures 13+1).

## 6. Anachronism check — measured, not assumed

Every bundled world zip was decoded and its region palettes enumerated
(`assets/eclipse/xboxworlds/*.zip`):

| world | distinct block ids | new ids vs the TU12 payload it derives from |
|---|---|---|
| tu1 | 69 | (authentic download) |
| tu12 | 128 | (authentic download) |
| tu14 | 152 | (authentic download) |
| tu19 | 106 | 0 |
| tu31 | 80 | 1 — `eclipse:classic_dead_bush` |
| tu69 | 89 | 0 |
| tu75 | 70 | 0 |

* **Base worlds (TU1/TU12/TU14)** are authentic 4J payloads, so their content is the
  ground truth for their era. Spot-checked against §5 and consistent: TU1 has none of
  the Beta 1.8+ families, TU12 has exactly the chiseled-stone-brick + mob-head + cocoa
  additions the TU12 changelog lists, TU14 has exactly the emerald/ender-chest/anvil/
  quartz/carpet/tripwire/flower-pot set the TU14 changelog lists.
* **Derived worlds (TU19/TU31/TU69/TU75)** are windows of the TU12 map. TU12's block set
  is a subset of every later era's set, so inherited content is period-safe by
  construction; only remap TARGETS can introduce an anachronism.
* The only remap target absent from the base payload is `dead_bush`, introduced in
  **JE Beta 1.6** — available ~4.5 years before TU31. Period-correct.
* Every other target (`mossy_cobblestone`, `stone_bricks`, `cracked_stone_bricks`,
  `mossy_stone_bricks`, `spruce_planks`, `spruce_log/leaves`, `oak_log/leaves`, `sand`,
  `gravel`, `snow_block`, `ice`, `fern`, `dandelion`, `poppy`) already exists in the
  authentic TU12 payload.
* Namespace check: the bundled worlds contain only `eclipse:classic_*` and
  `minecraft:air`. No modern or modded block (e.g. `eclipse:pale_oak_*`, which belongs
  to the Pale Garden feature, not the Classic area) leaks into the Xbox worlds.

**→ `tools/xboxworlds/variants.py` needs no mapping change. Left untouched.**

One deliberate deviation worth recording: TU19's `oak_trees()` rule converts every
birch/spruce/jungle tree to oak ("the only oaks world"). Birch, spruce and jungle wood
all existed by TU19 — this is an intentional artistic era-read documented in the
`variants.py` docstring, **not** an anachronism, so it was left alone.

## 7. World regeneration

**Not required.** No block id, remap table or world payload changed; only texture PNGs
and their generator were touched. The committed zip hashes in
`assets/eclipse/xboxworlds/manifest.json` and `xbox_staging/SOURCES_AND_LICENSES.md`
stay valid.

For reference, regeneration would be `python3 tools/xboxworlds/variants.py` followed by
`python3 tools/xboxworlds/frames.py` (the frames pass targets the final loot JSONs) —
do **not** run either for F-012.
