> pillar / bands + the `altar_aura_grade` shimmer). This plan is the **feedback-facing

> (`altar_aura_rim_*`, `altar_aura_spiral_*`, `altar_aura_powerup`) — zero collisions
> with the shipped `altar_aura_*` set (the `credits4_` precedent).

### 1.2 Island geometry (from `worldgen/structure/FloatingSanctumBuilder`)

- Island top: **ellipse rx 16 / rz 14**, floating `ISLAND_LIFT = 14` above the crater.
- Altar sits `ALTAR_ABOVE_GROUND = 4` above the island top ⇒ relative to the
  `ALTAR_CENTER` anchor: island surface = **y −4**, island underside ≈ **y −18**.
- 8 pillars on the r = 9 ring; 4 satellite islets with orbit shards (ring 2);
  debris rings r ≤ 13 (SanctumOrbitals); rune-lawn cells r ≈ 6–7.

### 1.3 Gaps (why the user still doesn't feel an ISLAND aura)

1. **Scale**: every near-field V1 element hugs the dais (r 2.2–6.4). Nothing marks the
   island EDGE (r 14–16), nothing converges from the rim to the altar, nothing lives
   under the floating island. From 60 blocks the island reads "altar with sparkles",
   not "sacred island".
2. **Stage transition**: on a level-up the new aura window just opens next tick — no
   pulse, no fade-in beat tied to the aura itself (the ceremony plays, but the aura
   layers pop).
3. **Veil boundary tell**: the grade is proximity-only ((1−d/72)²) — there is no
   noticeable "I just crossed into the aura" moment, and below L3 Veil is silent.
4. **Cutscene conflict**: `AltarAuraIdle`/`AltarAuraGrade` have NO cutscene gate. The
   End-arrival cutscene (`/dev event start endarrival`) parks the camera at the altar
   — aura executors + the GRADE pass fight the hero shots and the executor budget.
   Server beats use `ExpansionSequence.isAnyRunActive()`; the client-side equivalent
   is `cutscene/client/CameraDirector.isActive()` — used by neither aura class.
5. **Colour ladder**: V1 palette is constant violet/gold at every stage; the stages
   don't read as an evolution.

Nothing in V1 is dead/unused — all four cues are driven by `AltarAuraIdle`, the grade
registers at static init. V2 is purely additive.

## 2. Design — the layered island aura

Three ranges, every layer stage-gated, all WINDOWED (INTEGRATION.md §4):

- **Far (< 220)**: existing `altar_aura_pillar` (unchanged) — the horizon read.
- **Island scale (< 96)**: NEW rim ring + spiral streams around the island edge —
  the "hier ist was magisch" read the user asked for.
- **On-island (< 72)**: existing dais layers + Veil grade + NEW boundary tell +
  optional rune-halo displays.

### 2.1 Photon layer — new loop assets (one live executor per family via min/max stage)

Windows carry `minLevel`..`maxLevel` so each family swaps tiers instead of stacking
(caps the executor count):

- `altar_aura_rim_lo` (L1–2) / `altar_aura_rim_mid` (L3–4) / `altar_aura_rim_hi` (L5)
  — motes born on a circle **r 15.5, thickness 2.5** (covers the 14..16 ellipse), at
  island-top height (emitter shape at y −4 relative to the anchor), rising 2→7 blocks
  with orbital drift; plus a faint rim fog skirt and (mid/hi) occasional up-streamers
  on the pillar ring r 9. Density/height/colour per §3.
- `altar_aura_spiral_lo` (L2–3) / `altar_aura_spiral_hi` (L4+) — slow spiral streams
  converging rim → altar crown: carriers born on the rim circle, **negative `radial`
  (−0.10..−0.16) + `orbital` y 0.25..0.4 + gentle climb** (the `altar_indraw` /
  `arc_bolts` velocity pattern), short embedded trails (`with_module("trails", …)`
  as in `_orbit_band`). 2 arms (lo) / 4 arms + brighter heads (hi).
- `altar_aura_powerup` — ONE-SHOT burst (non-loop row): expanding ground ring wave
  altar → rim (BurstSpread circle, `start_speed` tuned to sweep r 0→16 in ~1.2 s),
  a vertical flash on the pillar, and a 2 s spark rain over the island. Fired only on
  stage-up (§5).

Authoring: new generator **`tools/photon/altar_aura2_fx.py`** (fxlib; copy the header
laws of `altar_aura_fx.py` — round-trip validate, `.fxproj` sibling, `CIRCLE_TEX`,
additive materials, `with_lights(sky=15, block=15)`, cull boxes sized to the island:
rim/spiral ±20 xz, −6..+12 y). House palette + per-stage colours from §3. Budgets:
each asset ≤ ~80 live particles.

### 2.2 Veil layer — extend `altar_aura_grade` (still ONE pass, GRADE priority)

- **[g4] boundary shimmer** (the "crossing the dome" tell): new uniform `Edge` (0..1),
  fed CPU-side from the camera distance to the aura shell **R_dome = 24**:
  `Edge = exp(−((d − 24)²) / (2·3²)) × stageFactor`, eased like `Aura`. In the shader:
  a narrow horizontal refraction ripple (≤ 1.4 px, Detail-gated) + a ~0.3 px chroma
  split, so walking onto the island gives one soft "surface tension" wobble and it
  fades once you are inside. Zero cost when `Edge ≈ 0` (same early-out style as [g1]).
- **`Gold` uniform** (0..1 per stage, §3): mixes the [g2] lift colour and [g3] tint
  from deep violet (L3) toward gold-white (L5), so the grade follows the colour ladder.
- Uniform rule: `Aura, Time, Detail` stay; ADD `Edge, Gold` in
  `shaders/program/altar_aura_grade.json` + `.fsh` + feeder (`AltarAuraGrade.feedPost`)
  in the same commit (additive-uniform rule, see the .fsh header).
- Keep `MIN_STAGE = 3` for the full grade, but `Edge` alone activates from **L2**
  (weak, 0.35×) so the boundary is noticeable before the shimmer era. The pass
  predicate becomes `eased > MIN_ACTIVE || edgeEased > MIN_ACTIVE`.
- Existing zone-grade precedents to imitate: `echo_grade.fsh` (zone grading; NB commit
  `431429c` — glsl-processor 0.2.3 NPEs on bare `return;`, use amount-scaled terms,
  never early-return) and `CreditsSkyFx.Pulse` (envelope shape for §5).

### 2.3 Optional block-display layer — rune halo (L4+)

Extend **`SanctumOrbitals`** (it already owns persistence, self-heal, the 40 t
interpolation transport, player gate and level scaling) with a third ring: **8
BlockDisplays** (amethyst cluster / purpur pillar / crying-obsidian mix per the
existing debris palette) on r ≈ 7 at **y +12** above the altar (above the corona),
slow counter-orbit + individual tumble, present only while `altarLevel >= 4`
(reconcile spawns/discards them exactly like the islet companions; new identity tags
`ring=3,slot=0..7`). Budget: 12 existing + 8 = **20 displays total** (« 150). They are
persistent spawn-chunk entities like the existing rings ⇒ NO `EclipseShutdownSweep`
hook needed (the F-080 sweep is for transient swarms only); the join-time tag
self-heal covers duplicates.

## 5. Stage-transition "aura power-up" beat

Trigger seam: **client-side in `AltarCeremonyFx.start(pos, level, crowd)`** (already
receives every organic level-up; zero server changes):

1. `t = ANTICIPATION_TICKS` (the burst beat): dispatch `altar_aura_powerup` via
   `PhotonFxRegistry.dispatch` at the anchor (ground offset −4) — ring wave sweeps
   altar → rim in ~1.2 s.
2. Same tick: `AltarAuraGrade.pulse()` — a `CreditsSkyFx.Pulse`-style envelope
   (attack 3 t, decay 30 t, adds up to +0.5 on top of `eased`, clamped 1.0) so the
   whole grade visibly brightens once.
3. `AltarAuraIdle.notifyStageUp(level)`: newly-eligible windows get
   `retryCountdown = 45` (the wave "unlocks" them — the new layer blooms right after
   the ring passes the rim instead of popping at t 0). Stage-tier swaps (rim lo→mid)
   release the old tier gracefully at the same moment.
4. Skip everything while `CameraDirector.isActive()` (cutscenes own the frame; the
   End-arrival erupt beat plays its own composition).

`/eclipse altar set` does NOT fire `FX_ALTAR_LEVELUP` (audit §1.1) — the beat is
testable via `/dev photon test eclipse:altar_aura_powerup` and organically via
milestone deposits.

## 6. Performance + lifecycle

- LOD: rim/spiral share the 88/96 near band; only the 1-beam pillar exists beyond.
  Idle cost while far: one distance check per window per tick (unchanged pattern).
- No per-tick allocation storms: windows are a static final array; the only per-tick
  allocation while open is the `anchor.add(…)` Vec3 (the shipped pattern). `Edge`
  math is scalar. `notifyStageUp` allocates nothing.
- Clean shutdown: Photon loops are client-side — released on logout
  (`PhotonFxRegistry.ClientReset`), dimension change, `reducedFx`, anchor loss (server
  stop clears anchors via `FxAnchors.onServerStopped` + client clear). The halo
  displays are persistent spawn-chunk entities (SanctumOrbitals contract) — no
  `EclipseShutdownSweep`/`forceClearNow` hook required; reconcile discards them on
  stage drop.
- Budgets: ≤80 particles/asset; 7/24 executors worst case; grade stays ONE pass at
  GRADE priority (still evicted first — "nur wenn frei" contract holds); +8 displays.
- `reducedFx`: all loops release instantly (existing gate), `Aura`+`Edge` targets 0,
  powerup dispatch is skipped by the registry budget rules; Quasar baseline untouched.
